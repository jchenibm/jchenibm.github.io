手机 Agent 办公

所有的复杂工程，全部在手机 App 上通过调度上千个 Agent 完成

Boris 大部分的工作在手机上完成，在 Claude App 左侧有"代码"选项卡，同时开启 5-10 个会话，每个会话运行着一堆 Agent。

目前大约有几百个 Agent 同时运行，每晚通常有几千个 Agent 在执行更深层次的任务。

Sloop 循环任务

使用 Cron 预约未来任务，可每分钟、每五分钟或每天运行

Sloop 是"最酷、最简单的方案"：让 Claude 使用 Cron（计划任务）来预约未来的任务。

实际应用场景：

  • 自动监控 PR，修复 CI 报错或自动 Rebase
  • 维护 CI 健康，自动修复挂掉的测试
  • 每 30 分钟抓取 Twitter 反馈并分类总结

Opus 4.7 转折点

从去年 5 月 Opus 4 发布，增长曲线开始爆发式上升

时间线：

  • 2024 年底：最初 6 个月不太好用，只有 10% 代码用它写
  • 2025 年 5 月：Opus 4 发布，增长曲线爆发
  • 随后：Opus 4.5, 4.6, 4.7 持续向上折射
  • 2025 年 10-11 月：达到临界点，模型可编写 100% 代码

本质上是"产品市场匹配"前六个月就开始研发，为"下一个更强的模型"而设计。

Anthropic 内部

全公司已无手写代码，所有 SQL 和基础构架由模型生成

领先的不是技术本身，而是组织流程：

  • 内部使用的模型和大家一样（Opus 4.7）
  • 所有事情上都使用 Claude
  • Claude 之间在 Slack 上自动沟通解决未知问题
  • 所有 SQL 语句都是模型写的

"吃自家的狗粮"至关重要，确保开发者用的和内部用的是一套东西。

印刷机类比

软件将像发短信一样成为全民本能

14 世纪欧洲印刷机：

  • 印刷前：欧洲只有 10% 的人识字
  • 印刷后 50 年：出版文献超过之前 1000 年总和
  • 书籍成本：下降 100 倍
  • 最终结果：全球识字率上升到 70%

软件领域类比：

"写软件"会变成像发短信一样自然的基本技能，比 Office 技能更普及。

例子：

写会计软件的最佳人选不是工程师，而是优秀的会计。他们最懂业务逻辑，编码只是最简单的环节。

提示词工程本质

多 Agent 协作功能本质上还是提示词工程

观众问题：

如何优化"分发任务给 Agent"的体验？什么时候该开启并行 Agent？

Boris 回答：

"在产品层面，这归根结底就是提示词工程。就是这么简单。"

4.7 的自主性：

模型已经开始自主启用"循环"功能。比如让它查询动态数据，它会说："我注意到数据随时间变化，我开个循环任务，每 30 分钟给你发报告。"

长远方向：

不应该由用户琢磨如何操控工具，那是产品设计问题。应该让模型更智能，通过提示词让这种行为变得像本能一样自然。

云端 vs 本地

几年后这都不重要了，模型会自己决定

观众问题：

未来会继续依赖云端中心化算力，还是转向本地 Agent？

Boris 回答：

"最根本的答案是：这以后都不重要了。"

我们正进入"模型能搞定一切"的阶段。几年后：

  • 模型负责所有代码
  • 自己启动 Agent
  • 自己构建环境
  • 判断用本地还是云端模型

这些决定未来不再由"工程师"来做，模型会代劳。

MCP 与 Computer Use

MCP 是核心答案，Computer Use 是保底方案

知识工作工具访问：

对于云端工具（Salesforce、Google Docs、Google Calendar），最简单的答案是 MCP。

MCP 连接器：

在 Claude AI 中使用的 MCP 连接器，可以接通各种云端服务。然后在 Co-work、Claude CLI 或 Claude Code 任何地方都能调用这些能力。

Computer Use：

对于没有 MCP 接口的系统，"计算机使用"是保底方案。Anthropic 在这方面处于领先地位，虽然速度慢，但在 4.7 加持下已经完成得相当出色。

Token 视角：

"不管是 MCP、CLI 还是 API，对模型来说都无所谓，那只是不同的 Token 而已。"

Routines 常规任务

服务器端运行的循环任务，关掉笔记本也继续跑

Sloop vs Routines：

  • Sloop：本地循环任务
  • Routines：服务器端常规任务

Routines 优势：

  • 运行在服务器端
  • 即使关掉笔记本也继续运行
  • 原理一样，但更持久

"循环就是未来的方向，如果你还没试过，强烈推荐。"
