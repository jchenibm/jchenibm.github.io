01第一层
基础机制

Claude Code 如何导航

智能体搜索像软件工程师一样工作——无需索引、无需嵌入，直接访问实时代码库。
工作方式

文件系统遍历

Claude 像工程师一样导航代码库：读取文件、使用 grep、跟随代码引用遍历文件系统。

本地运行 无索引
核心优势

始终最新

直接在实时代码库上工作——没有过时的嵌入或陈旧的索引。每次查询都能看到当前最新代码。

实时访问 数据新鲜
关键需求

起始上下文

需要足够的上下文来知道在哪里查找。CLAUDE.md 文件和技能提供了导航基础。

前期设置 上下文

智能体搜索的优势

与嵌入整个代码库的 RAG 工具不同，Claude 的智能体搜索避免了数据陈旧问题。无需维护嵌入管道——直接访问实时代码即可。

部署环境

数百万行单体仓库

在跨越数十年开发的数百万行代码库的生产环境中部署。

语言支持

企业级编程语言

在 C、C++、C#、Java、PHP 等语言中表现出色——尤其是在最新模型发布后，表现往往超乎预期。

系统架构

分布式系统

跨越多个独立仓库的数十个微服务，数千名开发者共同贡献。

03第三层
实践模式

配置模式

在成功的大型部署中反复出现的三种方法。
模式一

使代码库可导航

分层 CLAUDE.md 文件：根文件用于架构，子目录用于本地模式。权限配置引导哪些可以安全修改。

结构化 层次
模式二

主动维护

每 3-6 个月或主要模型发布后审查配置。帮助旧模型的指令可能会限制新模型。

演进 更新
模式三

指定负责人

在广泛发布前进行专门的基础设施投资。代理管理员角色：混合 PM/工程师拥有生态系统。

治理 负责人

分层 CLAUDE.md 模式

根文件：架构概述、测试标准、部署模式。子目录文件：模块特定约定、本地构建命令、领域特定规则。

核心原则

渐进式展示

并非所有专业知识都需要在每个会话中加载。技能按任务或目录激活，保持上下文专注且相关。

避免

知识孤岛

插件防止良好配置变得 tribal。打包有效的方法并通过托管市场分发。

投资

前期设置

投资代码库设置的团队看到更好的结果。可读的代码库 = 更好的导航 = 更高效的会话。
